## 一、代码改动清单

### 1.1 正确性修复（2 个）

| 提交 | 文件 | 内容 |
|---|---|---|
| `faefff4` | `src/tsdb.cpp` | **ZigZag 负时间戳编码错误**：`static_cast<uint64_t>(value) >> 63` 是逻辑右移（恒得 1），应为算术右移（全 1）。修复前 `-1000` 被编成 `0xFFFFFFFFFFFFF831`，解码回 `-9223372036854774809`，被范围过滤掉——**负时间戳的点只要经过 WAL 或 Flush 就永久读不到**。基线同样中招。 |
| `920a95a` | `src/tsdb.cpp` | **Aggregate 桶计算溢出**：`timestamp - start`、`quotient * window`、`bucket + window` 全部改用 `__int128`（`Int128`），floor 语义不变；桶起点做范围检查后窄化；桶尾在 128 位里与 `end` 取小。 |

> 说明：`static_assert(__cplusplus >= 202002L)` 固定在 `faefff4` 之后的提交里，保证不会在 C++17 下静默退化为实现定义行为。

### 1.2 测试框架可靠性

| 提交 | 文件 | 内容 |
|---|---|---|
| `c8912e5` | `tests/check.h`（新增）、`tests/tsdb_tests.cpp`、`tests/fault_injection.cpp` | 用 `CHECK` 宏替换全部 `assert`（功能测试 127 处、故障注入 8 处）。`CHECK` 抛 `test_support::CheckFailure`，消息带**表达式、文件、行号**；runner 捕获后**继续跑完**，最后按失败数返回非零。故障注入也改成 CHECK 并报出失败轮次。 |
| `ad715ed` | `CMakeLists.txt` | 新增 `TSDB_SANITIZE` 选项（`-fsanitize=address,undefined -fno-omit-frame-pointer -g`），作用于库和测试目标。 |

> 为什么必须改：Release 定义 `NDEBUG`，`assert` 被编译成空语句。**改之前 `ctest` 的“全绿”实际只验证了 `AssertOk`**，一开断言就立刻暴露了 `negative_ts_recovery` 失败（即上面的 ZigZag bug）。

## 二、测试改动

### 2.1 新增 10 个用例（26 → 36）

| 用例 | 断言什么 |
|---|---|
| `vector_append_order` | 两个 series 交错写入、跨 vector 扩容边界后，逐点时间戳与值仍有序正确 |
| `vector_replay_order` | 手工构造**降序** WAL 记录（200 先、100 后），重放走有序插入，且顺序能穿过 Flush 落到 SSTable |
| `duplicate_version_dedup` | 重放一条 version 0 的旧记录：只返回 1 个点、值来自 version 1；并断言 `wal_bytes_replayed > 0`，防止“重放没发生也通过” |
| `cow_read_view_isolation` | 游标建立后写入 100 点，旧游标仍只见原 100 点；跨 Flush 再验一次 |
| `cow_vector_reallocation` | 通过测试钩子读**真实 capacity**，写入超过该容量（实测 100 点 → capacity 128 → 写 129），证明原地追加必然 realloc；旧游标数据完好 |
| `empty_dataset` | 空 Scan / 空 Aggregate / 未写过的 series / `start == end` |
| `aggregate_buckets` | 负时间戳窗口、桶边界、空桶不返回、SUM/COUNT/MIN/MAX/AVG 全算 |
| `aggregate_extreme_range` | `start=INT64_MIN`、数据到 `INT64_MAX-1`（跨度 > INT64_MAX），全宽窗口与 1 ms 窗口的桶；并断言 `window_ms<=0`、`start>end` 被拒 |
| `extreme_timestamps` | `INT64_MIN` 经 WAL + SSTable 往返；注明 `[start,end)` 半开区间取不到 `INT64_MAX` |
| `zigzag_boundaries` | `INT64_MIN`、`INT64_MIN+1`、`-1`、`0`、`1`、`INT64_MAX-1` 先走 WAL 重放、再走 SSTable |

### 2.2 测试钩子（为可测量而不是靠推断）

`include/tsdb.h` 增加 `tsdb::testing::InspectSeriesBuffer(engine, series_id)`，返回 `{point_count, capacity}`。
vector 布局返回真实容量；`std::map` 布局返回 `nullopt`（没有容量概念），同一用例据此选择“按容量驱动”或“固定超量写入”。

## 三、测试结果

### 3.1 三套构建（36 个功能用例 + 50 轮故障注入）

| 构建 | 结果 |
|---|---|
| Release + CHECK | **36/36 通过**，`tsdb_fault_test` 50/50 |
| Debug + CHECK | **36/36 通过**，50/50 |
| ASan + UBSan | **36/36 通过**，无 sanitizer 报告，50/50 |

### 3.2 变异测试（证明用例能抓错）

| 变异 | 结果 |
|---|---|
| `AppendPoint` 改成永远 `push_back`（去掉有序插入） | `vector_replay_order` 失败：`CHECK failed: points[0].timestamp_ms == 100 ... at tests/tsdb_tests.cpp:877` |
| `ApplyFragment` 改成永远原地写（去掉 COW） | **ASan `heap-use-after-free`**：`cow_vector_reallocation` 读到被 realloc 释放的旧缓冲 |

> COW 这条只能靠 ASan 抓：游标持有旧 `end()` 迭代器，原地追加不会扩展可见范围，计数断言可能照样过；**悬垂迭代器才是真实危害**。

## 四、性能结果（真实磁盘，非 tmpfs）

### 4.1 三档规模（端到端，含最终 Flush 与后台合并收敛）

| 规模 | map | vector | 增益 |
|---|---:|---:|---:|
| 5M（3 轮中位） | 16.77 s / 298 k 点/s | 15.15 s / 330 k | +10.7% |
| 20M（2 轮中位） | 64.9 s / 308 k | 57.9 s / 346 k | +12.3% |
| **100M（各 3 轮）** | 314.7 / 320.1 / 357.1 s | 282.3 / 283.0 / 283.5 s | **+11.0~13.1%** |

- vector 三轮波动 **0.4%**，map 波动 **13.5%**（第 3 轮 fsync 累计 211 s，磁盘状态所致）；
- 按中位：vector 少用 **11.6%** 时间。

### 4.2 验收判定（100M）

| 要求 | 限值 | map | vector |
|---|---:|---:|---:|
| 导入耗时 | ≤ 60 min | 5.33 min | **4.72 min** |
| 峰值 RSS | ≤ 512 MiB | 229–236 MiB | **173–174 MiB** |
| 重启恢复 | ≤ 60 s | 12.3–13.0 s | 13.0–13.1 s |
| 磁盘 | — | 1.50 GB | 1.50 GB |

### 4.3 时间去向（100M，map）

| 项 | 次数 | 累计 | 性质 |
|---|---:|---:|---|
| WAL fsync | 100,000 | 177–211 s | 写路径串行，占写入循环 56–59%（每次约 1.8–2.1 ms，平均 1000 点/次） |
| Flush | 996–997 | 47–51 s | 持全局锁，写路径串行 |
| Compaction | 132–133 | 98–101 s | 独立线程，与写/Flush 重叠 |

### 4.4 RSS 归因（100M）

| 版本 | SSTable | Series 索引项 | 页索引项 | RSS |
|---|---:|---:|---:|---:|
| map | 56–80 | 140k–200k | 849k–909k | 229–236 MiB |
| vector | 68 | 165k–170k | 877k–883k | 173–174 MiB |

- 每文件约 2 500 条 series 索引 = 一个分片的 series 数，索引规模 ∝ 存活文件数；
- 估算常驻索引 **65–75 MB（约 RSS 的 30%）**；
- **剩余约 150 MB 未归因**，怀疑是 1000 次 Flush 的分配/释放造成的堆碎片，需要 massif 确认；
- 结论：暂不调 `max_live_sstables`；README 的 42 MiB 已标注为旧数据。

## 五、今日发现的三个“坑”（都值得写进汇报）

1. **`/tmp` 是 tmpfs（内存盘）**：早前的 5M A/B 与 1.27 M 点/s 全跑在内存上，fsync 几乎零成本，不能作为磁盘结论。已全部改到 `/dev/sdd` 重测。
2. **Release 下 `assert` 失效**：改 CHECK 之前，`ctest` 的“全绿”只覆盖了 `AssertOk`，因此漏掉了负数时间戳的数据丢失 bug。
3. **文档数字与代码脱节**：README 的 42 MiB、设计文档的 59 MiB/14.3 min 都早于页索引与写背压。README 已更新，设计文档待改。
